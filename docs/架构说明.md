# V6 记忆架构说明（为什么这么设计）

> 给想抄思路/想改参数的人。这一篇讲取舍，不讲 API。

---

## 1. 为什么不用向量数据库

一开始当然想过 RAG（`rag.py` 那套 bigram + 可选 embedding 就在仓库里），最后没把它当主记忆，原因有三：

1. **不可读**：出问题时要打开向量库反查，而纯文本 `mem_003.txt` 用记事本就能看、能改、能手动删。
2. **不可控衰减**：向量相似度没有"这条记忆最近还有用吗"的概念；而人脑会忘。分数模型才管得住"该忘的都忘掉"。
3. **成本**：embedding 要么本地跑一个小模型（多吃显存），要么调 API（要钱）。7B 机器上两者都不划算。

结论：**记忆 = 标签倒排 + 分数**。标签从文本里抽（bigram + 词表），分数管生死。检索是纯内存字典，亚毫秒。

## 2. 单一真源：memory_index.json

```
{
  "seq": 172,                 // 实体编号游标
  "decay_date": "2026-11-02", // 衰减水位（防重复衰减）
  "labels": {
    "[体检]": [{"target": "mem_100.txt", "fast": 22.0, "slow": 31.0}],
    "[课]":   [{"target": "mem_005.txt", "fast": 12.0, "slow": 40.0}]
  }
}
```

- 一个实体挂在多个标签下 → **同一文件的分数在每个标签里独立存**，命中哪个标签回血哪个
- 实体文件只放正文，头部一行 HTML 注释存 tags/created（不进 prompt）
- 检索顺序：query → 抽标签 → 并集去重 → 按 `rank` 排序 → 取 top-K

**为什么索引和正文分开**：正文可能几百字，索引只读分数，几百次检索也不用碰磁盘。

## 3. 双轨分数：快轨与慢轨

| 轨 | 上限 | 增长 | 衰减 | 代表什么 |
|---|---|---|---|---|
| `fast` | 40 | 每次命中 +10 | 每日掉得快 | 最近热度（"刚聊过"） |
| `slow` | 100 | 每次命中 +1 | 每日缓慢 | 长期沉淀（"反复提起过"） |

`rank = 0.6*slow/100 + 0.4*fast/40`

为什么两条轨：只有一条轨时，"刚说过一句"和"用户提过二十次"的排序会打架。
新记忆 `fast=40` 立刻能进 top2，但排第一的是 `slow` 高的老记忆——试过强行让新记忆永远第一，结果旧课表被今天的闲聊顶掉，反而更差。

---

## 4. 衰减、救援、熔断

- **衰减**：每天一次，`slow *= 0.9`（示例）、`fast` 掉得更狠；分数 ≤ 0 → 候选死亡
- **救援**：同一标签一天只回血一次（`RESCUE_PER_LABEL=1`），否则一条被反复提及的闲聊能永久续命
- **熔断**：一次衰减干掉超过 30% 活记忆 → 中止当天、记 `aborted=True`、按 14→7→3→1 天递减重算。
  仍然超限就**强制执行**——不强制的话 `decay_date` 永不推进，衰减永久冻结（早期就在这翻过车）
- **归档**：`sweep()` 把死亡实体 `shutil.move` 到 `Mem_Archive/`，不删内容。想复活就把文件挪回来重建索引

## 5. 输出门为什么必须有

本地 7B 有三个慢性病，prompt 治不好，只能代码兜：

1. **指令泄漏**：把 system 里的"用不确定的语气回答"当正文输出
2. **话题幻觉**：用户说"喝了（水）"，它答"小心醉了"
3. **不知道时间**：把"下午"当"早上"

所以输出统一过 `OutputGate.clean()`：删泄漏块、删含禁词的小句、必要时盖时间戳。
**和 SE 外挂的分工**：SE 负责"发现新的禁词"（云端复盘），OutputGate 负责"执行删除"（本地正则）。
两边都只做删句，不改写——改写容易越改越怪。

## 6. 三段式发信与 KV cache

```
[system] 人设（稳定，放最前）
[system] 记忆块 + 时间戳（变化，放尾部）
[history] 最近 3 轮
[user] 本次输入
```

人设在前不会被后面的变化打断缓存前缀；时间戳放记忆块末尾，模型才知道"现在几点"。
把时间戳塞进人设里试过，结果每次时间变化都击穿整段缓存。

## 7. 迁移教训（V5.2 → V6）

1. **旧分不能直接塞进 fast**：`FAST_CAP=40` 会把 45~70 的分变成"永远不加分"。搬运时把超出部分折算进 `slow`。
2. **台词会冒充记忆**：`【赛博参谋】xxx` 这类整段被写进库，模型会把台词当事实。
   解法是 `QUOTE_MARKERS` 词表 + 命中即墓碑（`fast=0`，永不进 prompt）。
3. **热替换 `.py` 不影响已跑进程**：改完必须重启；守护器会自动拉起，杀掉进程即可。
4. **索引缓存按 mtime 重载**：改规则/改索引不用重启，但**改代码必须重启**。
